Product Specification

Otherworld Reads

A quiet, personal reading tracker that helps you find your next book by feel — and sends you to a library or a local bookshop to get it. Not a social network, not a marketplace. A shelf that's yours.

01What this is

Otherworld Reads is a private reading shelf. You keep one current read, a TBR pile of what's next, a record of what you've finished and how it felt, and a short list of the libraries and bookshops you actually use.

It already does the first part well. This spec covers what it becomes: a shelf you can dress in a look you like, that knows real books so you never mistype a title, that can suggest something when you only know the mood you're in, and that hands you off to Libby or a local bookshop when you're ready to read it.

The one-sentence test. If a feature doesn't help you (a) remember what you read, (b) decide what to read next, or (c) actually get hold of it — it doesn't ship.

02Principles

Libraries first

Every "get this book" path leads to a library hold or an independent shop before it leads anywhere else. No Amazon links. Availability is shown honestly, including the wait.

Private by default

Your shelf is yours. No feed, no followers, no public profile. Sharing, if it ever exists, is an explicit one-off act — never a default state.

Feeling over rating

Books get a feeling (💛 Loved / Liked / Not for me) and moods, not a number out of five. Stars invite comparison; feelings invite memory.

Phone-shaped

Designed for one thumb at 11pm. Desktop is the bonus layout, not the baseline. Installable, works offline, opens instantly.

Nothing you must type twice

If a computer can know a book's title, author, cover, and year, you shouldn't be spelling them. Manual entry stays available — it's the fallback, not the default.

Quiet

No streaks, no badges, no yearly challenge counting down at you. Reading is not a productivity metric.

04The shelf model

Four surfaces, one book moving between them. On a phone they stack in this order; on a wide screen they sit in a three-column grid.

Current Read  ──finish──▶  Finished
     ▲                        │
   set current            (already read)
     │                        ▲
  TBR Pile  ◀──add──  Search · AI suggestions · Libraries

Objects

ObjectFieldsNotes
Book title, author, workKey, coverId, year, isbn, source Books added by search carry an Open Library workKey — the identity used for cover art and library lookups. Manually-added books have title + author only and degrade gracefully.
FinishedBook Book + finishedAt, feeling, moods[] Feeling is one of loved / liked / not-for-me. Moods are multi-select chips. Legacy entries with a numeric rating or freeform notes keep rendering.
Library label, officialName, url, overdriveKey, kind Today this is a free-text name and link. It becomes a real entity: a picked library system with an OverDrive key (enabling availability), a local bookshop, or a plain bookmark. label is whatever the reader calls it and is what the UI shows; officialName is what the library calls itself and is only used for disambiguation.
Vibe id A single stored string. The look is defined in CSS, not in data.
A deliberate reversal. Cover art was removed from the Current Read in v11 because typing an image URL by hand was tedious and usually skipped. With search-based adding, covers arrive for free from the Open Library CDN — so they come back, but only for books that have one. No placeholder boxes, no broken images: if there's no cover, the card is typographic, exactly as it is today.

05Choosing a vibe

The vibe is the app's whole look — background, palette, typography, texture. It is chosen once and can be changed any time, instantly, from anywhere. It is visual only: every label, every button, every piece of copy stays identical across vibes, so switching never costs you your bearings.

The flow

  1. First launch. Before the shelf appears, a full-screen picker: a grid of vibe cards, each rendering a miniature of the real UI in that vibe (a Current Read card, a chip, a button). No copy explaining them — you can see them.
  2. Tap one. The whole page transitions into it immediately behind the picker. There's no "confirm" step; the preview is the confirmation.
  3. Enter the shelf. Choice saved. Never asked again.
  4. Change it later. A vibe control in the header — a small palette glyph — opens the same picker. One tap re-skins the app in place. Scroll position, open panels, and any half-typed form are preserved.

The vibes

Otherworld default

Dark fantasy. Near-black with a violet bloom, sea-glass teal and old gold, Cinzel display type. The current look — existing users keep it and are never re-prompted.

Cottage

Warm paper and linen. Cream ground, sage and terracotta, a soft serif. Light-mode, gentle, the reading-nook end of the spectrum.

Celestial

Deep indigo and violet, silver and pale gold, a faint star-field behind the panels. Cool where Otherworld is warm.

Dark Academia

Oxblood, ink, and aged parchment. A proper old-style serif throughout, tight rules, library-card restraint.

Seaglass

Bright and coastal. Soft off-white, muted blue-green, sand. The lightest vibe — the one for reading outdoors.

Design decisions behind the vibe system

DecisionWhy
Visual only, not copy Renaming "The TBR Pile" per vibe is charming once and confusing forever — it breaks muscle memory, complicates search, and doubles the surface to maintain. Deferred, not discarded.
One token file per vibe Every vibe sets the same fixed set of CSS custom properties on :root. Components never reference a vibe by name, so a new vibe is one new file and one line in a registry — never a component edit.
Applied before first paint An inline script in <head> reads the saved vibe and stamps data-vibe on <html> before stylesheets resolve. No flash of the wrong theme on a cold start.
Contrast is non-negotiable Each vibe ships with measured contrast ratios. A vibe that can't hit WCAG AA on body text and interactive elements doesn't ship, however pretty it is.
Theme-color follows the vibe The PWA theme-color meta and the status bar update on switch, so an installed app doesn't have a dark-fantasy notch above a cream page.
Vibe is per-device, then synced Stored locally so it applies instantly offline, and mirrored to the cloud profile so a new device inherits your look instead of reverting to default.

06Finding a book

Today, adding a book means typing a title and an author into two boxes, with nothing checking your spelling. This replaces that with a single search field that suggests real books as you type.

The flow

  1. Tap "+ Add". One field, focused, labelled Title or author.
  2. Type. After a short pause (≈300 ms) and at least 3 characters, results appear beneath — up to 6, each showing cover thumbnail, title, author, and first-published year. Ranked by edition count, so the well-known book sorts above the obscure one with a similar name.
  3. Pick one. The book is added with full metadata. Done — no second screen, no confirm.
  4. Or don't. Below the results sits a permanent Add "what you typed" manually row, which opens the current two-field form. Self-published books, ARCs, a friend's manuscript, and anything Open Library has never heard of all still work.

Behaviour details

CaseWhat happens
OfflineThe search field falls back to manual entry with a quiet note. Adding a book never requires a network.
Slow responseResults are requested with a timeout. Past it, manual entry is offered — the UI never sits on a spinner.
Stale responsesEach keystroke's request supersedes the last; an out-of-order reply is discarded rather than overwriting fresher results.
DuplicateIf the picked book already sits on the TBR or in Finished, the result row says so and offers to jump to it instead of silently creating a second copy.
KeyboardArrow keys move through results, Enter picks, Escape closes. The list is a proper listbox so screen readers announce position and count.
Source: Open Library. Free, no API key, no rate-limit registration, permissive cross-origin access — and it's a project of the Internet Archive rather than a retailer, which suits the ethos. Verified working: a search for piranesi returns title, author, year, and cover ID in a single request.

07Reading & finishing

This flow is already right and changes very little. It's specified here because it's the spine of the app.

  1. Set a current read — from the TBR pile, from search, or by typing directly into the Current Read card. One book at a time, deliberately. (See Open questions.)
  2. It sits at the top of the app for as long as you're reading it. Title, author, and cover if there is one. Edit and Finish are the only actions.
  3. Finish & rate opens a small modal: How was it? (one of three feelings) and Vibe (any number of mood chips, optional). Both can be skipped.
  4. Save. The book moves to the top of Finished with today's date. Current Read empties and invites the next one.

The moods captured here — Cozy, Epic, Dark, Comfort-read, Romantic, Twisty, Slow-burn, Funny, Mind-expanding, Practical — are the same vocabulary the AI recommender uses. That's not a coincidence; it's the point. The more you finish, the better it knows your taste.

08Reading by vibe

The feature for when you've finished something and don't know what's next. You describe the reading experience you want, in your own words, and get a short list of real books back.

The flow

  1. "Find me something…" — a button on the TBR panel. Opens a sheet with mood chips (the same vocabulary as the finish form) and a free-text field: what are you in the mood for?
  2. Ask. Chips and text are sent along with a compressed picture of your taste: your recent loved books, your most-used moods, and — critically — a list of titles to exclude (everything on your shelf and everything you've already passed on).
  3. Five suggestions come back, each with a title, an author, and one or two sentences on why this, for you — tied to the mood you asked for and books you've loved. Not a blurb; a reason.
  4. Triage each one, in place. Three actions per card: + TBR Already read Pass. Cards animate out as you decide. "Already read" drops it into Finished with no feeling set, so you can fill that in later. "Pass" remembers it so it's never suggested again.
  5. Ask again if none of them landed. The exclusion list now includes everything you just passed on, so the second round is genuinely different.

How it works

ConcernApproach
Where the key lives Not in the browser. A small serverless function (Cloudflare Worker) holds the Anthropic API key and is the only thing that ever talks to the model. See Plan, Phase 5.
Who can call it Signed-in users only. The browser sends its Firebase ID token; the Worker verifies it and derives the user ID from the token — never from the request body.
How much A per-user daily cap (starting at 10 calls/day). The remaining count is shown in the sheet before you ask, so hitting the limit is never a surprise.
Model claude-opus-5, with structured output so the response is always a valid list of {title, author, why} — no prose parsing, no malformed-response handling in the UI.
Hallucinated books Every suggestion is checked against Open Library before it's shown. Anything that doesn't resolve to a real work is dropped silently. You never see a book that doesn't exist.
Failure Any error — offline, over quota, model unavailable — surfaces as one plain sentence and a Retry, inside the sheet. The rest of the app is unaffected.
Cost, honestly. At roughly 1.5k tokens in and 800 out per request, Opus 5 works out to about 2¢ per recommendation — so a user hitting the full 10/day cap costs about $0.24/day, or ~$7/month. Fine for you and a handful of friends; it does not scale to strangers on the open internet. Two levers exist if it needs to: lower the daily cap, or switch the Worker to Haiku 4.5 (~0.5¢/call, a quarter of the cost). The Worker is one line away from either. Decide when there's a real bill, not before.

09Getting the book

The part that makes this more than a list. Every book on the TBR pile can answer "can I get this right now?" — and the answer is grounded in a real library's collection, not a guess.

Setting up your library

  1. The Libraries panel gains an Add library flow that searches actual library systems by name or place, rather than asking for a name and a URL.
  2. Picking one stores its OverDrive key. That key is what unlocks availability.
  3. Name it yourself. The next field is What do you call it?, pre-filled with the library's official name and fully editable. "Mom's card", "the good one", "County" — whatever you'd actually say out loud. That label is what the app shows everywhere afterwards; the official name is kept underneath, in smaller type, only where two entries would otherwise be indistinguishable. Renaming is always available from Edit and never touches the stored key, so a rename can't break availability.
  4. Multiple libraries are supported — many readers have a city card and a county card, which is exactly why the names have to be yours. The first one is treated as primary for availability checks, and the order is yours to change.
  5. Bookshops and plain links are still first-class and named the same way: an entry can be a library, a bookshop, or a bookmark. Only libraries get availability.

On a TBR book

Once a library is set, each TBR entry shows a borrow row:

StateShown asTapping it
Available nowAvailable now · ebook / audiobookOpens the title in Libby, ready to borrow.
On hold~15 day wait · 168 holds on 164 copiesOpens the title in Libby, ready to place a hold.
Not in collectionNot at County — the row uses your name for the library, not its official oneOffers a Libby search, plus a link to buy it from an independent bookshop.
No library setAdd a library to see availabilityJumps to the Libraries panel.
Lookup failed / offlineRow is hidden entirely—
Feasibility, checked. OverDrive's public catalogue endpoint (the one Libby's own web app uses) returns availability, hold counts, and estimated wait days for a given library, and permits cross-origin requests. A live query against a real library system for Piranesi returned ownedCopies: 164, holdsCount: 168, estimatedWaitDays: 15 — exactly the data this design needs.
And the risk. That endpoint is undocumented and unsupported. It can change or start refusing browser requests without warning. So availability is designed as an enhancement, never a dependency: if the lookup fails for any reason, the borrow row simply doesn't render, and the plain "Search this on Libby" link — which is a normal URL and cannot break — is always present underneath. Every phase of this feature must be shippable with the enhancement switched off.

Buying, when borrowing isn't an option

Where a purchase link is warranted, it goes to Bookshop.org, which splits revenue with independent bookshops, or to a specific local shop the reader has added themselves. There is no Amazon link anywhere in the app, and no affiliate tracking of any kind unless the reader is told about it plainly.

10Data & privacy

QuestionAnswer
Where does my shelf live?In your browser when signed out. In your own document in Firestore when signed in, readable and writable only by you.
Can anyone else see it?No. There is no sharing surface, no public URL, no feed.
What leaves the device?Book searches go to Open Library. Availability checks go to OverDrive with a library key and a title — no account, no card number, no identity. AI requests go to the Worker with your moods, a short taste summary, and your sign-in token.
Does the AI see my whole shelf?No — a compressed summary: recent loved titles, frequent moods, and an exclusion list. Not your full history, not your dates, not your notes.
Is anything logged?The Worker logs a per-user call count for rate limiting and nothing else. No prompts, no results, no titles.
Can I leave?Export to JSON, and delete-everything, are both first-class actions. Leaving should be as easy as arriving.

11Accessibility & performance

Targets

  • WCAG AA contrast in every vibe, verified per release
  • Every action reachable by keyboard; visible focus rings
  • Modals trap focus and restore it on close
  • 16px minimum on inputs (no iOS zoom-on-focus)
  • 44px minimum tap targets
  • Live regions announce shelf changes
  • prefers-reduced-motion honoured for all transitions

Budgets

  • Interactive in under 1s on a mid-range phone, cold
  • Full offline function for everything except search, availability, and AI
  • Under 150 KB of JavaScript, uncompressed, excluding the Firebase SDK
  • No layout shift on load — the vibe applies before first paint
  • No blocking spinner anywhere; every remote call has a timeout and a fallback

12Decisions & non-goals

DecisionRationale
No build step Native ES modules and plain CSS, served straight from GitHub Pages. Deploying stays git push, and the project can be picked up after six months away without fighting a toolchain.
Static frontend + one serverless function The only thing that genuinely needs a server is holding the AI key. Everything else the browser can do itself. A single Worker beats a whole backend to maintain.
Enhancements degrade, never block Search, availability, and AI are all optional layers over a shelf that works offline with nothing but typing. Any one of them can fail and the app is still the app.
Vibes are visual only (for now) Ships in a fraction of the time, and keeps every label stable while the app is still growing.
Open Library over Google Books No key, no quota registration, and a non-commercial custodian. Better fit for a library-first app.
Suggestions are verified before display A recommender that invents books is worse than no recommender. Cross-checking costs one request and buys complete trust in the list.

Explicitly not building

  • Social features — no following, no feeds, no comments, no public shelves.
  • Reading challenges, streaks, or stats dashboards — counting is not the point.
  • Progress tracking (page counts, % complete) — a book is either current or it isn't.
  • Amazon or Goodreads integration — against the premise.
  • User-authored custom vibes — deferred; a theme editor is its own product.
  • Native apps — the PWA installs to the home screen and that's enough.

13Open questions

QuestionLeaning
Should more than one book be "current" at once? Plenty of people read a novel and a non-fiction book in parallel. Yes, eventually — but as a small list capped at two or three, not an unbounded shelf. Revisit after Phase 3, when the data model is cleaner.
Should a "did not finish" state exist, distinct from finishing with Not for me? Probably. DNF is a real and different feeling. Cheap to add; needs a home in the finish modal.
Should series be tracked, so book 2 can be suggested automatically? Open Library exposes some series data, inconsistently. Interesting, low confidence, not before Phase 5.
Should the AI be able to see the whole finished list rather than a summary? Better suggestions, more cost, more data leaving the device. Start with the summary and see whether the results are good enough.
Is there ever a shared shelf — a partner or a book club seeing the same TBR? Genuinely useful, and the single biggest departure from "private by default." Needs its own spec.
